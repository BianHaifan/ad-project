# Android 求职者资料页结构化输入改造计划

## 目标

统一 Candidate 的 Profile、Resume 和 Job preferences 编辑体验：将可枚举的数据从平铺标签或自由文本改为选择器；保留确实需要自由表达的文本输入。仅改 Android UI 与本地 UI 状态，不变更 Spring API、OpenAPI、数据库或 ML 推荐逻辑。

## 交互约定

| 字段类型 | 交互方式 | 适用字段 |
|---|---|---|
| 单选枚举 | 选择器行，打开下拉/底部单选列表 | 性别、工作方式、最低薪资（清除项在列表首项） |
| 多选枚举 | 选择器行，打开可搜索的底部勾选列表；页面仅显示已选摘要 | 技能、期望职位、期望地点、雇佣类型 |
| 数字 | 带吸附效果的滚轮选择器 | 年龄、最低月薪 |
| 日期 | 已有月度日期选择器 | 工作经历起止月份 |
| 自由文本 | 常规输入框 | 姓名、手机号、所在地补充、出生地、个人标题、简介、职位名、公司名、经历描述 |

自由输入的标题、地点和技能不会被删除：它们只会移入相应的选择面板内的“添加自定义项”，避免主页面杂乱，同时保持现有 API 能接收任意字符串的能力。

## 实施范围

### 1. 复用式选择器组件

- 在 Candidate profile feature 内新增或整理小型 Compose 组件：单选 selector、多选 selector、可搜索勾选列表、数值滚轮。
- 所有组件使用项目现有 Ad 颜色、间距和错误文案；无新第三方依赖。
- 选择面板必须支持取消、确认、已选数/摘要和错误提示；确认前不写入服务端。

### 2. Profile 编辑页

- 性别从平铺 FilterChip 改为单选选择器。
- 年龄改为 16–80 的滚轮；支持“未填写”。
- 地点提供已整理地点列表选择，并在面板内保留自定义地点。
- 姓名、Headline、Phone、Birthplace 保持文本输入；头像流程不改。

### 3. Resume 编辑页

- Skills 从全量 FlowRow 标签改为“选择技能”入口，打开可搜索多选列表；自定义技能在面板内添加。
- Summary、职位、公司、工作描述保持输入框；经历日期继续使用现有月份选择器，Present 保持明确开关。

### 4. Job preferences 编辑页

- Desired titles、Preferred locations 改为可搜索多选列表，并保留面板内自定义项。
- Workplace type、Employment type 改为多选列表，不再平铺标签。
- Minimum monthly salary 改为带“Not specified”的数值滚轮，继续以 SGD/月保存。
- 保存请求、版本冲突处理、推荐刷新提示保持原样。

## 验收标准

- 三个页面不再直接平铺完整技能、职位、地点、薪资或枚举标签。
- 已有 Profile、Resume、Preference 数据打开后可正确预选，并保存为同一 API 请求格式。
- 多选项可搜索、增删、取消和确认；自定义项不会在重新打开后丢失。
- 年龄和最低薪资无须键盘手动输入，且可以清空。
- 保存中、加载、错误、版本冲突及空数据状态不回归。
- Android 单元测试与 debug APK 构建通过；模拟器分别手测 Profile、Resume 和 Job preferences 保存一次。

## 风险与控制

- Compose Material 没有现成跨版本数字滚轮时，使用项目内封装的 `LazyColumn` 吸附滚轮，不引入库。
- 不限制用户只能使用目录中的技能、标题或地点；自定义项留在选择面板，避免降低资料表达能力。
- 不修改 `ml-service`、Agent、后端迁移或推荐评分公式。
