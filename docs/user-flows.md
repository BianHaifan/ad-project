# 用户流程

## 1. 第一条垂直切片

这是首个必须端到端跑通的开发目标。

```text
Recruiter 登录
→ 创建职位草稿
→ 填写职位信息
→ 发布职位
→ Candidate Android 获取职位列表
→ 打开职位详情
→ 选择默认简历并确认投递
→ 后端创建 Application
→ Recruiter 查看申请人列表
→ 将状态更新为 SCREENING 或 INTERVIEW
→ Candidate 查看我的申请和状态历史
```

### 必须验证的异常路径

- 未登录投递：返回 401，Android 跳转登录
- 角色错误：返回 403
- 重复投递：返回 409，并显示已投递提示
- 职位不存在：返回 404
- 职位已关闭或下架：返回 409
- 简历不存在：引导创建或上传简历
- ML 服务超时：显示“匹配结果暂不可用”，仍允许投递

## 2. 求职者注册与简历流程

```text
注册 Candidate
→ 登录
→ 填写基本资料
→ 创建或上传简历
→ 解析为结构化字段
→ 用户校对
→ 设置为默认简历
```

简历解析失败时必须允许用户手工填写，不能阻断主流程。

## 3. 招聘者发布职位流程

```text
注册 Recruiter
→ 创建/加入公司
→ 等待管理员审核
→ 新建职位草稿
→ 填写标题、描述、地点、类型、薪资和技能
→ 预览
→ 发布
```

只有已审核的公司和正常状态的招聘者可以发布职位。

## 4. 申请状态机

```text
SUBMITTED
  ├──→ SCREENING
  │       ├──→ INTERVIEW
  │       │       ├──→ OFFERED
  │       │       └──→ REJECTED
  │       └──→ REJECTED
  └──→ WITHDRAWN（仅求职者）
```

规则：

- Recruiter 可以执行业务审核状态流转，但不能设置 `WITHDRAWN`。
- Candidate 只能将自己的非终态申请设置为 `WITHDRAWN`。
- `OFFERED`、`REJECTED`、`WITHDRAWN` 是 MVP 终态。
- 禁止跳转或重复设置时返回 409。

## 5. ML 职位推荐流程

```text
离线准备训练/验证/测试数据
→ 训练基线模型和候选推荐模型
→ 使用独立测试集比较 Precision@K、Recall@K、NDCG@K 等指标
→ 注册选定模型版本
→ Candidate 打开职位首页
→ Spring Boot 生成候选职位并组装用户/职位特征
→ ML 服务返回 Top-N 排序、分数、理由和 modelVersion
→ Spring Boot 过滤不可见职位并保存推荐曝光
→ Android 展示个性化推荐列表
→ 浏览、收藏、投递和忽略行为成为后续训练信号
```

新用户使用简历与偏好的内容特征解决冷启动。ML 调用设置超时和降级；失败时回退到规则排序，不得把推荐分数作为投递资格条件。

## 6. AI Agent 流程

```text
用户输入“把我默认简历里的年龄改成 28”
→ Spring Boot 创建 Agent Run
→ Agent 调用 get_my_default_resume
→ Agent 调用 preview_resume_patch，生成 age: 原值 → 28
→ Android 展示将修改的简历、字段和新值
→ 用户确认
→ Agent 调用 apply_resume_patch（携带用户身份和幂等键）
→ Spring Boot 再次验证简历所有权并保存新版本
→ Agent 返回完成结果和可撤销/查看入口
```

如果“年龄”对应的是出生日期等需要更多信息的结构化字段，Agent 必须追问，不得自行猜测。读取类指令可以直接执行；写入、投递、撤回、发送和删除类指令必须确认。

## 7. Figma 补齐顺序

只为当前开发切片补页面：

1. 发布/编辑职位
2. 投递确认与投递成功
3. 招聘者申请人列表
4. 招聘者申请详情和状态操作
5. 求职者我的申请与状态详情
6. 登录/注册
7. 简历编辑/上传
8. 精简管理员审核

前五项完成后即可开始第一条垂直切片开发，不必等待全部页面高保真。
