# 权限与安全规范

## 1. 权限模型

采用 RBAC（角色权限）加资源所有权校验。

仅判断 `role == RECRUITER` 不足以授权访问；还必须确认招聘者所属公司与职位/申请所属公司一致。

## 2. 权限矩阵

| 能力 | Candidate | Recruiter | Admin |
|---|---:|---:|---:|
| 查看已发布职位 | ✓ | ✓ | ✓ |
| 修改自己的资料 | ✓ | ✓ | ✓ |
| 管理自己的简历 | ✓ | — | — |
| 投递职位 | ✓ | — | — |
| 查看自己的申请 | ✓ | — | — |
| 撤回自己的申请 | ✓ | — | — |
| 创建/编辑本公司职位 | — | ✓ | — |
| 查看本公司申请人 | — | ✓ | — |
| 修改本公司申请状态 | — | ✓ | — |
| 审核公司和招聘者 | — | — | ✓ |
| 下架任意职位 | — | — | ✓ |
| 禁用用户 | — | — | ✓ |
| 查看他人完整简历 | — | 仅申请本公司职位者 | 按审核需要限制 |

## 3. 资源级规则

- Candidate 只能读取和修改 `candidate_id == currentUser.id` 的资源。
- Recruiter 只能管理 `job.company_id == currentRecruiter.company_id` 的职位。
- Recruiter 只有在申请属于本公司职位时才能查看对应简历快照。
- Recruiter 查看的是投递快照，不应因求职者后来修改简历而改变历史申请内容。
- Admin 高风险操作必须填写原因并写入审计日志。
- 为避免资源枚举，访问无权查看的具体资源可以统一返回 404。

## 4. 认证规则

- 密码使用成熟的单向密码哈希算法和安全参数。
- Access Token 短时有效；Refresh Token 可撤销并安全保存。
- Android 不把长期令牌写入普通明文偏好设置。
- Web 优先使用安全、HttpOnly、SameSite 合理配置的 Cookie；若使用其他方式，必须单独评估 XSS/CSRF。
- 登出、禁用账户和密码变更应使相关刷新令牌失效。
- 登录、注册、Agent 和上传接口设置频率限制。

## 5. 输入与文件安全

- 所有请求 DTO 使用白名单校验；Entity 不直接作为请求体。
- 职位描述、简历文本和 Agent 输入按普通不可信文本处理。
- 上传只允许明确类型和大小，生成服务器端文件名，并考虑恶意文件扫描。
- 前端输出用户内容时防止 XSS；不执行简历或职位中的 HTML/脚本。
- 数据库查询必须参数化，由 JPA/Repository 安全构造。

## 6. Agent 特殊权限

- Agent 只能调用当前场景注册的工具。
- Agent 的有效权限等于“当前用户权限”与“Agent 白名单工具权限”的交集。
- Candidate Agent 可以管理本人的资料、简历、收藏和申请，但不能调用 Recruiter/Admin 工具。
- Recruiter Agent 只能操作本公司资源，且同样受职位所有权和状态机约束。
- 模型输出不能直接被视为授权结果或数据库命令。
- 写工具在服务层重新执行与普通接口相同的鉴权和校验。
- 修改简历、收藏、投递、撤回申请、发送消息、删除内容等可产生副作用的操作必须展示目标与变更预览并由用户确认。
- 每个确认动作包含目标、变更摘要、有效期和一次性标识。
- Prompt injection 不得使 Agent 泄露系统提示、密钥或其他用户数据。

Agent 工具示例：

| 工具 | 类型 | Candidate 是否可用 | 是否确认 |
|---|---|---:|---:|
| `get_my_profile` | 读取 | ✓ | 否 |
| `get_my_resume` | 读取 | ✓ | 否 |
| `preview_resume_patch` | 预览 | ✓ | 否 |
| `apply_resume_patch` | 写入 | ✓，仅本人简历 | 是 |
| `list_job_recommendations` | 读取 | ✓ | 否 |
| `save_job` | 写入 | ✓ | 是 |
| `create_application` | 高影响写入 | ✓ | 是，每次确认 |
| `update_application_status` | 招聘者写入 | Candidate 不可用 | 是 |
| `disable_user` | 管理员写入 | Candidate/Recruiter 不可用 | 是 |

## 7. 敏感数据与日志

禁止记录：

- 明文密码
- Access/Refresh Token
- API Key
- 不必要的完整简历原文
- 未脱敏手机号、身份证件等信息

允许记录最小必要信息：用户 ID、资源 ID、动作、结果、错误码、traceId 和耗时。

## 8. 安全验收

- 每个受保护接口至少包含未登录、错误角色和错误所有权测试。
- 测试 Candidate A 不能访问 Candidate B 的简历与申请。
- 测试 Recruiter A 不能访问 Company B 的职位和申请。
- 测试 Agent 不能绕过上述限制。
- 管理员高风险操作有完整审计记录。
