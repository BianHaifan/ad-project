# 产品需求说明（MVP）

## 1. 产品目标

构建一个类似 BOSS 直聘和 LinkedIn 的智能招聘平台，使求职者能够在 Android 端浏览和投递职位，使招聘者能够在网页端发布职位并处理申请。系统使用团队自行训练的机器学习模型为求职者推荐和排序职位，并提供能够通过自然语言执行用户操作的 AI Agent。

## 2. 用户角色

### 求职者 Candidate

- 注册、登录和维护个人资料
- 创建或上传一份默认简历
- 浏览、搜索和查看职位
- 查看 ML 个性化职位推荐、排序分数和推荐理由
- 投递职位并查看处理进度
- 通过自然语言让 AI Agent 执行本人有权完成的操作

### 招聘者 Recruiter

- 注册、登录并绑定公司
- 创建、编辑、发布和关闭职位
- 查看职位收到的申请
- 查看求职者简历与匹配结果
- 修改申请状态并填写备注

### 管理员 Admin

- 查看并审核公司、招聘者和职位
- 下架违规职位或禁用违规账户
- 查看基础运营统计与审计记录

管理员在 MVP 中只实现精简的审核与状态管理，不实现复杂运营后台。

## 3. MVP 核心业务流程

```text
招聘者创建并发布职位
→ 职位进入可浏览状态
→ 求职者在 Android 端查看职位列表和详情
→ 自训练推荐模型对候选职位进行排序并提供推荐理由
→ 求职者确认使用默认简历投递
→ 招聘者在网页端查看申请
→ 招聘者将申请更新为筛选中、面试、录用或拒绝
→ 求职者在 Android 端查看最新状态
```

## 4. MVP 功能范围

### P0：必须完成

- 邮箱或用户名密码注册与登录
- Candidate、Recruiter、Admin 三种角色与权限隔离
- 求职者个人资料和一份默认简历
- 招聘者公司资料与职位发布
- 职位列表、基础搜索、职位详情
- 投递、重复投递拦截、投递记录
- 招聘者申请人列表和状态流转
- 求职者申请进度
- 管理员基础审核
- 自行训练的职位推荐模型、Top-N 推荐结果和评估报告
- 一个能通过工具执行用户操作的 AI Agent 流程
- OpenAPI 文档、关键自动化测试和可演示部署

### P1：MVP 完成后增加

- 收藏职位
- 面试通知与简单站内消息
- 多份简历
- 更丰富的搜索和筛选
- AI 简历改写、面试问题生成
- 招聘者候选人排序

### P2：当前不承诺

- 社区动态、课程平台、会员付费
- 实时音视频面试
- 完整即时聊天系统
- 企业级多租户和复杂组织权限
- 生产规模实时推荐基础设施或无确认自动投递

## 5. ML 与 AI Agent 边界

### Machine Learning

ML 的主要任务是个性化职位推荐，而不是简单调用第三方模型得到一个匹配分数。模型必须由团队完成数据准备、训练、评估、版本管理和推理服务。

- 输入：求职者简历与偏好、职位特征、匿名化行为信号（浏览、收藏、投递、忽略）
- 输出：按分数排序的 Top-N 职位、推荐理由、模型版本和生成时间
- 首版至少实现一个可复现基线模型，再实现并比较一个团队训练的推荐模型
- 可选方法包括内容特征模型、Learning-to-Rank、隐式反馈协同过滤或混合推荐
- 数据不足时使用课程允许的公开数据、团队标注样本和合成行为，但必须在论文中明确来源与局限
- 离线评估优先使用 Precision@K、Recall@K、NDCG@K、MAP 或 HitRate@K，并与基线比较
- 训练集、验证集和测试集必须隔离；避免把未来行为泄露到训练特征
- 冷启动用户使用简历与偏好进行内容推荐，不能返回空白首页
- 推荐服务失败时回退到最新职位或规则排序，不影响浏览和投递
- 职位详情可展示由推荐模型或解释模块产生的分数与技能依据，但它不是完整推荐系统的唯一输出

### AI Agent

Agent 是软件的自然语言操作层，而不只是聊天或生成建议。它把用户指令转成计划并调用现有业务工具。例如：“把我默认简历里的年龄改成 28”“收藏这个职位”“展示我的投递记录”。

Agent 至少包含：

1. 理解用户指令和目标对象；
2. 读取当前用户及完成任务所需的最小数据；
3. 选择一个或多个受控工具；
4. 对写操作展示字段级变更预览；
5. 获得用户明确确认后执行；
6. 返回操作结果，并保存执行步骤和审计信息。

Agent 的权限不高于当前登录用户。Candidate Agent 不能执行 Recruiter/Admin 操作，也不能读取其他用户数据。投递、撤回申请、发送消息、删除内容等高影响操作必须逐次确认，禁止后台无确认自动执行。

## 6. MVP 页面清单

### Android 求职者端

- 启动/登录/注册/角色提示
- 职位列表
- 职位详情（现有 Figma 节点 `2004:2`）
- 简历查看与编辑/上传
- 投递确认与结果
- 我的申请与申请详情
- 个人资料
- AI Agent 对话、操作计划、变更预览与执行结果

### 招聘者网页端

- 登录
- Dashboard
- 职位管理
- 发布/编辑职位
- 申请人列表
- 申请详情与状态操作
- 公司资料

### 管理员网页端

- 登录
- 审核列表
- 公司/职位/用户详情
- 审核、下架和禁用确认

## 7. 全局验收标准

- 未登录用户不能投递、发布职位或查看受保护数据
- 求职者只能查看和修改自己的资料、简历与申请
- 招聘者只能管理所属公司的职位和申请
- 同一求职者不能对同一职位重复投递
- 已关闭、已下架或未发布职位不能被投递
- 每次申请状态变化必须记录操作者、原状态、新状态和时间
- ML/LLM 服务异常时核心 CRUD 流程仍可使用
- 推荐模型必须可以复现训练并输出独立测试集指标
- Agent 写操作必须经过确认，并产生可查询的执行记录
- 所有列表页处理 loading、empty、error 三种状态
- 所有高风险操作提供明确确认和结果反馈
