# 开发阶段计划

## 阶段 0：范围与契约

目标：全组对“做什么、不做什么、数据怎么流动”达成一致。

- 评审本目录全部工程规范
- 确定课程对版本、部署、数据库和论文的额外要求
- 将现有 Figma 页面映射到 MVP 页面清单
- 补第一条垂直切片缺失页面的低保真稿
- 冻结第一批实体、状态枚举和 API

退出条件：垂直切片每一步都有页面、API、数据实体和验收标准。

## 阶段 1：工程骨架

- 创建 Spring Boot 工程和模块边界
- 创建 Android Kotlin + Compose 工程
- 创建 React + TypeScript 工程
- 创建 OpenAPI 契约目录
- 配置 MySQL、本地环境、迁移工具和 CI
- 实现统一错误格式、认证骨架和健康检查

退出条件：三端可启动，Spring Boot 可访问数据库，客户端可调用健康检查。

## 阶段 2：第一条垂直切片

按此顺序交付：

1. Recruiter 登录与公司测试数据
2. 创建、编辑、发布职位
3. Android 职位列表和详情
4. Candidate 默认简历
5. Candidate 投递
6. Recruiter 申请人列表和详情
7. 申请状态流转
8. Candidate 我的申请和时间线
9. 端到端测试

退出条件：两种客户端通过真实 Spring Boot API 和 MySQL 完成全流程。

## 阶段 3：自训练职位推荐模型

- 定义推荐目标、正负反馈和数据集/合成数据方案
- 构建热门职位或内容相似度基线
- 建立可复现的训练、验证、测试和评估脚本
- 训练推荐模型并与基线比较 Precision@K、Recall@K、NDCG@K 等指标
- 保存数据版本、特征版本、模型版本和实验结果
- 实现内部 Top-N 推荐 API
- Spring Boot 增加超时、缓存和降级
- Android 职位首页展示个性化推荐，详情展示推荐理由
- 保存模型版本与评估结果用于论文

退出条件：训练过程可复现，模型优于选定基线，推荐可解释、可降级且不阻断浏览和投递。

## 阶段 4：AI Agent

- 定义 Agent 可以代替用户完成的操作和禁止操作
- 实现读取资料、读取/预览/修改简历、职位推荐和申请等白名单工具
- 实现自然语言指令 → 计划 → 工具调用 → 结果的多步骤流程
- 增加字段级变更预览、用户确认、幂等和过期机制
- 用“把默认简历年龄改成 28”作为第一条端到端 Agent 用例
- 保存 Run/Step 审计数据
- 添加越权、失败和 Prompt injection 测试

退出条件：演示中能看到工具调用、确认和结果，不只是一次聊天回复。

## 阶段 5：管理员与补充功能

- 精简公司/职位/用户审核
- 面试通知或简单消息
- 搜索筛选、收藏等 P1 功能
- 只在时间允许时增加社区、学习等非核心模块

## 阶段 6：验收与论文材料

- 真机和浏览器端到端演示
- 性能、安全和异常测试
- 截图对比修正 Figma 还原
- 导出 ER 图、架构图、流程图、API 和测试报告
- 汇总 ML 指标、Agent 案例和局限性
- 准备演示脚本、数据和故障降级方案

## 任务拆分模板

每个交给 Codex 或组员的任务必须包含：

```text
目标：
允许修改的目录：
参考文档：
参考 Figma 节点：
API 契约：
验收标准：
必须运行的测试：
禁止修改的部分：
```

一个任务应对应一个可以独立验证的功能，不使用“完成整个系统”之类无法验收的描述。
